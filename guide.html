1. 이 사이트는 어떻게 돌아가나요?

부분어디에 있나비용
사이트 화면 (이 파일들)GitHub Pages — 무료 웹사이트 호스팅무료
로그인 · 회원정보 · 업무 · 회의록 목록 · 사업 기록Google Firebase — 구글의 무료 데이터 저장소무료 (학생회 규모로는 무료 한도의 1%도 안 씀)
회의록 · 기획안 원본 파일지금처럼 구글 드라이브 / 구글 독스 (사이트엔 링크만)무료
가장 중요한 원칙: GitHub와 Firebase를 모두 학생회 공용 gmail 계정으로 만드세요. 그러면 인수인계는 "공용 gmail 비밀번호 전달" 한 번으로 끝납니다. 개인 계정으로 만들면 그 사람이 졸업할 때 사이트도 같이 사라질 수 있어요.
같은 이유로, 지금 회장 개인 계정 소유인 회의록 구글 드라이브 폴더도 공용 gmail로 옮겨 두는 걸 강력히 추천해요. (드라이브에서 폴더 우클릭 → 공유 → 공용 gmail을 편집자로 추가 → 그 사람 옆 메뉴에서 "소유권 이전") 회장이 졸업하고 계정을 지우면 회의록이 통째로 사라질 수 있습니다.

2. 처음 설치하기 (딱 한 번)

준비물: PC, 학생회 공용 gmail 계정, 이 가이드와 함께 받은 사이트 폴더(압축을 풀어두세요).

모든 단계에서 학생회 공용 gmail로 로그인한 상태인지 꼭 확인하세요. (크롬 오른쪽 위 프로필 사진)

1Firebase 프로젝트 만들기

  1. console.firebase.google.com 접속 → 프로젝트 만들기 (또는 "Firebase 프로젝트 시작하기")
  2. 이름: 아무거나 영어로 (예: kubio-council) → 약관 동의 → 계속
  3. "Google 애널리틱스" → 사용 안 함으로 끄기 → 프로젝트 만들기
화면이 영어로 나오면 같은 위치의 영어 버튼을 누르면 돼요. (Create project, Continue …)

2구글 로그인 켜기

  1. 왼쪽 메뉴 빌드(Build) → Authentication → 시작하기
  2. Sign-in method 탭 → 목록에서 Google 선택
  3. 오른쪽 위 스위치 사용 설정 켜기 → "프로젝트 지원 이메일"에 공용 gmail 선택 → 저장

3데이터 저장소(Firestore) 만들기

  1. 왼쪽 메뉴 빌드 → Firestore Database → 데이터베이스 만들기
  2. 위치: asia-northeast3 (Seoul) 선택 (나중에 못 바꿔요) → 다음
  3. 프로덕션 모드에서 시작 선택 → 만들기
  4. 만들어지면 위쪽 규칙(Rules) 탭 클릭
  5. 사이트 폴더 안의 firestore.rules 파일을 메모장으로 열어서 (우클릭 → 연결 프로그램 → 메모장 / 맥은 텍스트편집기) 내용을 전부 복사
  6. 규칙 편집 칸의 기존 내용을 전부 지우고 붙여넣기
  7. 붙여넣은 내용에서 OWNER_EMAIL@gmail.com 부분을 학생회 공용 gmail 주소로 바꾸기 (작은따옴표 '는 그대로 두기, 영어 소문자로)
  8. 게시(Publish) 클릭
이 규칙이 "승인된 학생회원만 연락망을 볼 수 있게" 지켜주는 자물쇠예요. 꼭 게시까지 눌러 주세요.

4웹 앱 등록하고 열쇠 값 복사하기

  1. 왼쪽 위 ⚙️ 톱니바퀴 → 프로젝트 설정
  2. 아래쪽 "내 앱" 칸에서 </> (웹) 아이콘 클릭
  3. 앱 닉네임: 아무거나 (예: site) · "Firebase 호스팅 설정"은 체크하지 않기 → 앱 등록
  4. 화면에 나오는 코드 중 아래 4줄의 따옴표 안 값을 메모장에 복사해 두세요. 
    apiKey: "AIza……",
authDomain: "kubio-council.firebaseapp.com",
projectId: "kubio-council",
appId: "1:1234……:web:ab12……",
    (storageBucket, messagingSenderId 등 다른 줄은 필요 없어요)
apiKey는 "비밀번호"가 아니라 "주소" 같은 거라 공개돼도 괜찮아요. 실제 보안은 3단계의 규칙이 지킵니다. GitHub가 "API 키가 노출되었다"고 경고 메일을 보내도 무시해도 됩니다.

5GitHub에 사이트 올리기

  1. github.com에 학생회 공용 gmail로 가입. 아이디(Username)는 사이트 주소에 들어가요 (예: kubio-council)
  2. 오른쪽 위 + → New repository
  3. Repository name: 짧은 영어 (예: site) · Public 선택 → Create repository
  4. 다음 화면에서 "uploading an existing file" 파란 링크 클릭
  5. 압축 푼 사이트 폴더를 열어서, 폴더 안의 내용물 전부(index.html, guide.html, css 폴더, js 폴더, firestore.rules, README.md)를 선택해서 브라우저 화면에 끌어다 놓기
    ⚠️ 폴더 자체가 아니라 폴더 "안의 것들"을 끌어다 놓아야 해요. 크롬이나 엣지를 쓰세요.
  6. 업로드가 끝나면 아래 초록 Commit changes

6설정 파일에 열쇠 값 넣기 (GitHub에서 바로)

  1. 저장소 화면에서 js 폴더 → config.js 클릭
  2. 오른쪽 위 ✏️ 연필 아이콘 (Edit this file)
  3. 아래처럼 따옴표 안을 채우기 (따옴표·쉼표는 지우지 마세요) 
    ownerEmail: "학생회공용주소@gmail.com",

firebase: {
  apiKey: "4단계에서 복사한 값",
  authDomain: "4단계에서 복사한 값",
  projectId: "4단계에서 복사한 값",
  appId: "4단계에서 복사한 값"
}
  4. 오른쪽 위 초록 Commit changes… → 다시 Commit changes

7사이트 공개 켜기 (GitHub Pages)

  1. 저장소 위쪽 Settings 탭 → 왼쪽 메뉴 Pages
  2. Source: Deploy from a branch · Branch: main / /(root) → Save
  3. 1~3분 기다린 뒤 새로고침하면 위쪽에 사이트 주소가 떠요:
    https://아이디.github.io/저장소이름/

8Firebase에 사이트 주소 알려주기

  1. Firebase 콘솔 → Authentication → 설정(Settings) 탭 → 승인된 도메인(Authorized domains)
  2. 도메인 추가 → 아이디.github.io 입력 (앞에 https:// 나 뒤에 /저장소이름 은 빼고) → 추가
이걸 안 하면 로그인할 때 "This domain is not authorized" 오류가 나요.

9첫 로그인 & 기본 설정

  1. 사이트 주소로 들어가서 공용 gmail로 로그인 → 가입 신청 없이 바로 들어가져요 (최고 관리자)
  2. 관리 → 사이트 설정 → 설정 바꾸기에서
    • 기수와 학생회 이름 (예: 제29대 / 윤슬)
    • 국서 목록은 회장단·내무국·소통국·홍보국·재무국·대외협력국으로 미리 들어가 있어요. 국이 생기거나 없어지면 여기서 한 줄에 하나씩 고치면 돼요
    • 직책 목록 (회장, 부회장, 국장, 국원으로 미리 들어가 있어요)
    • 회의록 구글 드라이브 폴더 주소 (드라이브에서 폴더 열고 주소창 주소 복사)
  3. 저장하면 설치 끝!

설치 중 막히면, 막힌 화면을 캡처해서 Claude 같은 AI에게 이 가이드와 함께 보여주며 물어보면 대부분 해결돼요.

3. 회원들에게 공유하고 쓰기 시작하기

  1. 회장·부회장이 먼저 사이트에 로그인해서 가입 신청
  2. 공용 gmail로 로그인 → 관리 탭 → 회장·부회장 승인 → 각각 편집 눌러서 "회장단 권한" 체크 → 저장
    이제부터는 회장단이 자기 계정으로 가입 승인을 할 수 있어요. 공용 gmail은 비상용으로만 쓰면 됩니다.
  3. 학생회 단톡방에 사이트 주소 공지 → 각자 로그인 → 가입 신청 → 회장단이 승인
카카오톡에서 링크를 누르면 카톡 안의 브라우저에서는 구글 로그인이 막혀 있어요. 사이트가 자동으로 "외부 브라우저로 열기" 버튼을 보여주니, 그걸 누르면 돼요. 공지할 때 "크롬/사파리로 열어주세요" 한 줄 같이 써 주면 좋아요. 휴대폰 홈 화면에 추가해 두면 앱처럼 쓸 수 있어요.

각 메뉴 사용법

메뉴쓰는 법
비상연락망승인된 회원이 국서별·직책순으로 자동 정리. 번호를 누르면 바로 전화. [명단 복사]로 카톡에 붙여넣기, [인쇄]로 종이 연락망. 번호가 바뀌면 각자 [내 정보 수정].
업무 캘린더사업의 사업 날짜(시행일)는 색이 꽉 찬 칸으로, 국서별 업무 마감은 연한 칸으로 표시돼요. 1박 2일 사업은 이틀 모두 표시돼요. 날짜 칸을 누르거나 [+ 업무 추가] → "할 일 / 담당 국 / 마감일". 예) 소통국 · 개강파티 가수요조사 공지글 작성 · 8/31. 끝나면 목록에서 체크. 국서별 색깔·필터로 보기.
회의록지금 학생회 회의록은 1·2학년 모두, 지난 학생회 회의록은 그 학생회에 함께 있었던 사람(예: 29대 1학년 → 30대 2학년)만 볼 수 있어요. 사업 아카이브는 모든 학생회 것이 계속 보여요. 지금 학생회 회의록만 기본으로 보이고, 이전 학생회 회의록은 아래 "지난 학생회 회의록"에 학생회별로 접혀 있어요. [새 학생회로 넘기기] 때 자동으로 넘어가요. OB는 자기가 활동한 학생회의 회의록만 OB 기록실에서 볼 수 있어요. 회의록은 지금처럼 구글 독스로 작성 → 공유 링크를 [+ 회의록 등록]에 붙여넣기. 월별로 정리되고 검색됨.
사업 기획안지금 학생회의 사업. 사업마다 담당 국·상태(기획중/진행중/완료)·기획안 링크. 추가할 때 학생회 이름(예: 제29대 윤슬)이 자동으로 기록돼요. 사업 카드의 [+ 국서별 업무 분배하기]로 "소통국 · 공지글 작성 · 마감일"처럼 국서마다 할 일을 한 번에 넣으면 업무 캘린더에도 표시되고, 카드에 진행률(예: 2/3 완료)이 보여요. 끝나면 상태를 '완료'로 바꾸고 "다음 기수에게 남길 말"을 꼭 적어주세요.
사업 아카이브역대 학생회 사업이 "제29대 윤슬"처럼 학생회별로 쌓여요. [참고해서 새로 기획하기]를 누르면 이전 기획안을 참고 링크로 붙인 채 새 사업이 만들어지고, 그때의 업무 분배표도 불러와서 마감일만 새로 넣으면 돼요. 사이트를 쓰기 전 학생회 자료는 [+ 지난 사업 기록하기]로 기수·이름과 함께 옮겨 두세요.
소통방자유게시판: 지금 활동 중인 학생회원끼리 자유롭게 글·댓글을 남기는 곳. 학생회를 넘기면 이전 글은 "제○○대 자유게시판"으로 접혀요.
선배들의 한마디 (타임캡슐): 2학년만 쓰고 2학년끼리만 볼 수 있어요(1학년에게는 "준비 중 🔒"만 보여요). [새 학생회로 넘기기]를 누르면 그때의 1학년(다음 학생회의 2학년)에게 공개돼요. 새로 들어온 1학년에게는 보이지 않아요.
관리 (회장단만)가입 승인/반려, 회장단 권한 부여, 임기 종료 처리, 사이트 설정.

임기를 마친 사람(OB)은 무엇을 볼 수 있나요?

임기 종료된 사람도 로그인은 계속 할 수 있어요. 대신 "OB 기록실" 화면만 보여요.

  • 볼 수 있는 것: 나의 학생회 활동 이력(예: 제29대 윤슬 · 재무국 국장), 그 학생회의 회의록, 함께했던 학생회 멤버 명단(이름·국서·직책·전화번호 — 같은 학생회였던 사람끼리만, 본인이 [내 정보]에서 공개에 동의한 경우만), 그 학생회가 했던 사업과 기획안 링크
  • 볼 수 없는 것: 지금 학생회의 연락망(전화번호), 지금 학생회 회의록, 업무 캘린더, 관리 화면. 수정도 할 수 없어요

멤버 명단은 [새 학생회로 넘기기]를 누르는 순간 기록돼요. 탈퇴한 사람은 OB 기록실도 볼 수 없어요.

중간에 학생회를 그만두는 사람이 생기면

  • 회장단이 처리: 관리 → 회원 관리 → 그 사람 [편집] → [탈퇴 처리]
  • 본인이 직접: 사이트 위쪽 [내 정보] → [학생회 탈퇴]

탈퇴하면 바로 사이트에 못 들어오고 연락망에서 빠져요. 개인정보 보호를 위해 전화번호는 삭제되고, 그 사람이 남긴 업무·회의록·사업 기록은 그대로 남아요. 나중에 다시 들어오게 되면 로그인 후 [다시 신청하기] → 회장단 승인으로 복귀할 수 있어요.

⚠️ 회장단 권한이 있는 사람이 탈퇴할 때는, 다른 회장단에게 권한이 있는지 먼저 확인하세요.

4. 매년 새 학생회에 물려주기 (10분)

  1. 새로 들어오는 사람이 있다면 사이트에 로그인해서 가입 신청 → 현 회장단이 승인
  2. 새 회장·부회장에게 회장단 권한 체크 (이게 먼저 돼 있어야 넘기기가 돼요)
  3. 관리 → 새 학생회로 넘기기에서 새 기수와 학생회 이름을 넣고, 아래 목록에서 새 학생회에서도 계속 활동할 회원을 체크 (회원이 입력한 학생회 학년이 1학년인 사람은 자동으로 체크돼 있어요. 남는 사람은 넘긴 뒤 자동으로 2학년이 돼요)
    → 체크 안 된 회원은 임기 종료(연락망에서 빠지고, 로그인하면 OB 기록실만 보임), 이전 학생회 사업은 이름과 함께 아카이브로, 사이트 위쪽 이름도 바뀜
    → 계속 활동하는 회원에게는 "국서·직책이 바뀌었으면 수정해 주세요" 안내가 떠요
  4. 새 회장단이 로그인해서, 넘기기를 누른 사람(이전 회장단) 계정을 회원 관리에서 임기 종료
  5. 학생회 공용 gmail 비밀번호와 이 가이드(사이트주소/guide.html)를 새 회장단에게 전달 → 새 회장단은 비밀번호를 바꾸고, 구글 계정 관리 → 보안에서 복구 이메일·복구 전화번호를 새 회장 것으로 변경 (이걸 안 하면 나중에 계정이 잠겼을 때 되찾을 방법이 없어요)
공용 gmail 하나로 GitHub · Firebase · 회의록 드라이브가 모두 연결돼 있으니, 이 계정만 잘 넘기면 사이트는 몇 년이고 그대로 이어져요.

5. 문제가 생겼을 때

증상해결
"데모 모드"라고 뜸6단계 config.js의 firebase 값이 비어 있어요. 다시 확인 후 저장, 2분 뒤 새로고침.
로그인 시 "This domain is not authorized" / "unauthorized-domain"8단계 승인된 도메인 추가를 확인하세요.
로그인 창이 안 뜸 / "disallowed_useragent"카톡·인스타 안 브라우저예요. 크롬·사파리로 열기.
"권한이 없습니다" 오류아직 승인 전이거나, 3단계 규칙이 게시되지 않았어요. 공용 gmail로 로그인했는데도 그렇다면 규칙 속 이메일과 config.js의 ownerEmail이 정확히 같은지(소문자) 확인.
공용 gmail로 로그인했는데 가입 신청서가 뜸config.js의 ownerEmail 주소가 틀렸어요. 고친 뒤 새로고침.
GitHub에서 수정했는데 사이트가 그대로반영까지 1~3분 걸려요. 그래도 같으면 Ctrl+Shift+R (맥: Cmd+Shift+R)로 강력 새로고침.
회장단 권한자가 모두 사라져 아무도 승인을 못 함공용 gmail로 로그인하면 항상 관리자예요. 거기서 다시 권한 부여.
학생회 이름에 오타가 있음관리 → 설정 바꾸기에서 고치고 "오타 수정이에요"에 체크 후 저장. (체크 안 하고 기수를 바꾸면 새 학생회로 넘어간 걸로 처리돼요)
국 이름을 바꿨더니 예전 업무가 회색으로 보임정상이에요. 해당 업무를 눌러 새 국으로 다시 선택하면 돼요.

절대 하지 말아야 할 것

  • Firebase 프로젝트 삭제, GitHub 저장소 삭제 → 모든 기록이 사라져요.
  • Firestore 규칙을 allow read, write: if true; 로 바꾸기 → 누구나 연락망을 볼 수 있게 돼요.
  • 공용 gmail 비밀번호를 단톡방에 올리기.
